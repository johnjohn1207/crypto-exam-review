SECTION 1

選擇密文攻擊 (CCA) 與解密預言機（Decryption Oracle）

🧠 直觀大腦模型：從 CPA 到 CCA 的能力躍遷
CPA 安全性（期中範圍）：加密預言機

「即使允許你選擇任意明文要求我加密，你依然無法區分我的密文究竟加密了 $M_0$ 還是 $M_1$。」

攻擊者被動接收密文，不能將密文送給解密者觀測解密行為。

CCA 安全性（期末範圍）：加密＋解密預言機

「即使允許你選擇任意明文加密，同時允許你提交任意密文要求我解密（唯獨不能直接提交挑戰密文 $C^*$），你依然無法區分。」

實務情境：伺服器解析收到的封包，攻擊者故意篡改密文並監控伺服器是否崩潰、報錯或延遲。

CCA 安全性的 Library 庫形式化定義（投影片 P.39）

方案 $\Sigma$ 為 CCA 安全，若真實庫 $\mathcal{L}_{\Sigma}^{\text{cca-real}}$ 與隨機庫 $\mathcal{L}_{\Sigma}^{\text{cca-rand}}$ 對於所有多項式時間區分器 $\mathcal{A}$ 均為計算上不可區分（$\mathcal{L}_{\text{cca-real}} \approx \mathcal{L}_{\text{cca-rand}}$）。

真實庫 $\mathcal{L}_{\Sigma}^{\text{cca-real}}$ 真實金鑰運算
$K \leftarrow \Sigma.\mathcal{K}$
cca.enc(M):
  $C := \Sigma.\text{Enc}(K, M)$
  return $C$
cca.dec(C):
  return $\Sigma.\text{Dec}(K, C)$
隨機庫 $\mathcal{L}_{\Sigma}^{\text{cca-rand}}$ 字典映射 + 洩漏過濾
$K \leftarrow \Sigma.\mathcal{K}$, $\mathcal{D} := \text{empty map}$
cca.enc(M):
  $C \leftarrow \Sigma.\mathcal{C}(|M|)$ // 隨機密文
  $\mathcal{D}[C] := M$ // 記錄對應關係
  return $C$
cca.dec(C):
  if $\mathcal{D}[C]$ defined: return $\mathcal{D}[C]$
  return $\Sigma.\text{Dec}(K, C)$ // 遭篡改密文回落真實解密
關鍵審計細節： 隨機庫中，只有自己加密出來且記錄在字典 $\mathcal{D}$ 中的密文才能保證解出原明文；凡是攻擊者篡改過的新密文 $C'$ 都不在 $\mathcal{D}$ 中，會直接回落至真實解密 $\Sigma.\text{Dec}(K, C')$。如果該加密方案允許密文篡改影響明文，攻擊者就能直接看穿真實庫與隨機庫的差異！
SECTION 2

延展性（Malleability）與 Null-Oracle 攻擊全解析

1. 延展性（Malleability）的精確定義（投影片 P.24）

若給定未知明文 $M$ 的密文 $C$，攻擊者能在不知道密鑰 $K$ 的情況下，構造出新的密文 $C' \neq C$，使得其解密結果 $M' = \text{Dec}(K, C')$ 與原始明文 $M$ 存在可預測的數學關係（例如 $M' = M \oplus \Delta$），則該加密方案具有延展性（Malleable）。

定理：任何具備延展性（Malleable）的加密方案，絕對不可能是 CCA 安全的！
（CTR 模式、CBC 模式、One-Time Pad、CFB、OFB 通通具有延展性，因此單獨使用時全都破 CCA 安全性！）

2. Null-Oracle 逐位元盲解推導（投影片 P.20-31）

1-bit 洩漏破全盤

假設伺服器解密 CTR 密文時，若解密出的明文中含有空字元（Null byte `0x00`），軟體就會崩潰或拋出錯誤，這就形成了一個只有 1 個 bit 輸出的預言機： $$\text{nulloracle}(C) = \begin{cases} \text{true}, & \text{若 } \text{CTR.Dec}(K, C) \text{ 包含 } 0x00 \\ \text{false}, & \text{否則} \end{cases}$$

【破解末位元組原理】數學抵消機制

令目標明文末字節為未知數 $b$，即 $M = M' \parallel b$。攻擊者猜測值為 $g \in \{0x01, 0x02, \dots, 0xFF\}$。
攻擊者將密文末字節 XOR 上 $g$，構造 $C' = C \oplus (\dots 00 \parallel g)$： $$\text{CTR.Dec}(K, C') = M \oplus (\dots 00 \parallel g) = M' \parallel (b \oplus g)$$ 當且僅當猜測值 $g = b$ 時，$b \oplus g = b \oplus b = 0x00$！
此時 $\text{nulloracle}(C')$ 立即返回 true（系統崩潰），攻擊者當場精確斷定：末位元組必為 $g$！

全明文還原演算法 $\mathcal{A}_{\text{null-oracle}}$（投影片 P.29） 
n := |C_1 || ... || C_l|               // 明文字節長度
M := ""
for i = 1 to n:
    for each g in {0x01, ..., 0xFF}:    // 最多 255 次測試
        Delta := (00)^n
        Delta[i] := g                  // 僅在第 i 個 byte 置入猜測值
        if nulloracle(C ^ (0^lambda || Delta)):
            M := M || g                // 命中 0x00！還原第 i 個 byte
            break
return M
攻擊情境 查詢複雜度 16 位元組區塊運算量 性質
真正暴力窮舉明文 $256^n$（指數級） $256^{16} \approx 10^{38}$ 次（宇宙尺度，不可能） 無法攻破
Null-Oracle 延展性攻擊 $\le 255 \times n$（線性級） $255 \times 16 \approx 4,080$ 次（不到 1 秒！） 極度致命，完全破解
SECTION 3

真實世界漏洞：PKCS#7 Padding Oracle 攻擊（POODLE 原理）

1. PKCS#7 填充規範與 CBC 模式解密機制（投影片 P.34）

CBC 模式要求明文必須對齊 16 位元組（128 bits）。不足時採用 PKCS#7 規範填充：缺 1 個字節填 `0x01`，缺 2 個字節填 `0x02 0x02`，若剛好整除則補一整塊 16 個 `0x10`。

CBC 解密公式核心：
$$P_k = \text{Dec}_K(C_k) \oplus C_{k-1} = I_k \oplus C_{k-1}$$ 其中 $I_k = \text{Dec}_K(C_k)$ 為區塊密碼解密後的「中間值（Intermediate Value）」。

伺服器解密後會校驗末端 Padding。若 Padding 格式錯誤，舊版 SSL/TLS、SSH 會回報「Padding Invalid」或產生不同延遲。 這直接給了攻擊者一個判定「$P_k$ 末端是否符合有效 Padding」的預言機！

步驟 A：鎖定目標字節

攻擊者截獲密文區塊 $(C_{k-1}, C_k)$。將 $C_{k-1}$ 的最後一個字節替換為隨機猜測值 $r$。

步驟 B：反推中間值 $I_k$

當伺服器回報 Padding Valid 時，代表解密末字節剛好是 `0x01`！ 因此 $I_k[16] \oplus r = 0x01 \implies \mathbf{I_k[16] = r \oplus 0x01}$！中間值被徹底揭露！

步驟 C：還原真實明文 $P_k$

既然有了真實的 $I_k[16]$，直接與攔截到的原始密文 $C_{k-1}[16]$ 做 XOR： $$\mathbf{P_k[16] = I_k[16] \oplus C_{k-1}[16]}$$ 完全不需要密鑰 $K$！

Timing Attack (Lucky 13)
解密時進行虛擬運算的時間微秒差異洩漏 Padding 長度。
Apple iMessage (gzip)
解密後 gzip 解壓縮成功/失敗作為 Oracle 洩漏明文字元。
XML / JSON Parser
解析語法錯誤（語意標籤不閉合）洩漏解密字串。
SECTION 4

期末必考形式證明：區分器演算法與推導步驟

證明一：1-bit 延展性必定攻破 CCA 安全性（投影片 P.40-41）

必背核心證明

方案定義：$Enc(K, M): R \leftarrow \{0,1\}^\lambda, S := F(K, R) \oplus M$；密文為 $R \parallel S$。
待證命題：該方案具備 CPA 安全性，但非 CCA 安全（Not CCA-secure）。

區分器 $\mathcal{A}$ 演算法構造：
M <- {0, 1}^lambda                         // 任意選取一個測試明文
Delta := arbitrary nonzero string          // 任選一個非零字串 (例如 0x01...00)
R || S := cca.enc(M)                       // 調用加密預言機
M' := cca.dec(R || (S ^ Delta))            // 篡改密文後半部並提交解密預言機
return M' == (M ^ Delta)                   // 檢查關係是否成立
優勢推導步驟（分步清晰）：
  1. 在真實庫 $\mathcal{L}_{\text{cca-real}}$ 中：
    解密演算法計算 $F(K, R) \oplus (S \oplus \Delta) = (F(K, R) \oplus S) \oplus \Delta = M \oplus \Delta$。
    因此恆有 $M' = M \oplus \Delta$。回傳 1 的機率： $$\Pr[\mathcal{A} \Rightarrow 1 \mid \mathcal{L}_{\text{cca-real}}] = 1$$
  2. 在隨機庫 $\mathcal{L}_{\text{cca-rand}}$ 中：
    篡改後的密文 $R \parallel (S \oplus \Delta)$ 由於 $\Delta \neq 0$，因此不在字典 $\mathcal{D}$ 中，解密請求回落至真實解密函數 $\Sigma.\text{Dec}(K, \cdot)$。
    但隨機庫中的 $S$ 是均勻隨機生成的，與明文 $M$ 完全獨立！因此解密出的 $M'$ 也是獨立均勻隨機字串。
    其剛好等於 $M \oplus \Delta$ 的機率僅為： $$\Pr[\mathcal{A} \Rightarrow 1 \mid \mathcal{L}_{\text{cca-rand}}] = \frac{1}{2^\lambda}$$
  3. 計算優勢（Advantage）： $$\mathbf{\text{Adv}_{\Sigma}^{\text{cca}}(\mathcal{A}) = \left| 1 - \frac{1}{2^\lambda} \right| \approx 1}$$ 優勢為 Non-negligible（極大），故該方案徹底違反 CCA 安全性。$\blacksquare$

證明二：Frankenstein 拼湊密文偽造攻擊（投影片 P.42-44）

進階難題考點

進階方案：$Enc(K, M): R \leftarrow \{0,1\}^\lambda, S := F(K, R) \oplus F(K, M)$，密文為 $R \parallel S$（$F$ 為 PRP，解密需調用 $F^{-1}$）。
特性：由於 $M$ 經過了非線性的 PRP 處理，單位的 bit-flipping 無法湊效。但攻擊者可以使用「科學怪人 Frankenstein 拼裝法」攻破！

區分器 $\mathcal{A}_{\text{Frankenstein}}$ 構造：
M <- {0, 1}^lambda
R1 || S1 := cca.enc(M)                     // 對同一個 M 加密第一次
R2 || S2 := cca.enc(M)                     // 對同一個 M 加密第二次
M1* := cca.dec(R1 || S2)                   // 交叉交換前半部與後半部
M2* := cca.dec(R2 || S1)                   // 交叉交換前半部與後半部
return M1* == M2*                          // 檢查兩次解密是否必然相等！
數學恆等式證明：
$S_1 = F(K, R_1) \oplus F(K, M)$
$S_2 = F(K, R_2) \oplus F(K, M)$
解密 $R_1 \parallel S_2$ 時，PRP 反求前輸入為：$F(K, R_1) \oplus S_2 = \mathbf{F(K, R_1) \oplus F(K, R_2) \oplus F(K, M)}$
解密 $R_2 \parallel S_1$ 時，PRP 反求前輸入為：$F(K, R_2) \oplus S_1 = \mathbf{F(K, R_2) \oplus F(K, R_1) \oplus F(K, M)}$

因為 XOR 滿足交換律，兩者的輸入完全相同，故解密結果必然 $M_1^* = M_2^*$！
在真實庫中回傳 1 的機率為 $1$；在隨機庫中因均未記錄在字典，兩者隨機相等機率為 $2^{-\lambda}$。Advantage $\approx 1$！

SECTION 5

訊息認證碼 (MAC) 與三種組合範式終極對比

1. MAC 的本質與不可偽造性（EUF-CMA）

密碼學雜湊（Hash）不需要密鑰，只能防範傳輸過程中的隨機位元錯誤；而 MAC（Message Authentication Code）必須持有共享密鑰 $K$，提供訊息真實性（Authenticity）與完整性（Integrity）。即使攻擊者看過大量自選訊息的 Tag，也無法偽造出任何全新訊息的合法 Tag。

PRF 直接作為 MAC：令 $T = F(K, M)$。若 $F$ 是安全 PRF，則該 MAC 是計算上不可偽造的（投影片 P.53）。

2. 三大組合範式終極對比（Encrypt & MAC Combos）

考題必出比較表
Encrypt-then-MAC (EtM) 黃金推薦
$C := \text{Enc}(K_e, M)$
$T := \text{MAC}(K_m, C)$
傳輸：$C \parallel T$

解密邏輯：先驗證 MAC！若 $\text{MAC}(K_m, C) \neq T$ 立即回傳 `err`，完全不執行解密！

CPA: 是 | CCA: 是
工業代表：IPsec, TLS 1.3
Encrypt-and-MAC (E&M) 嚴重漏洞
$C := \text{Enc}(K_e, M)$
$T := \text{MAC}(K_m, \mathbf{M})$
傳輸：$C \parallel T$

致命缺陷：MAC 算在「明文 $M$」上！因為 MAC 往往是確定性的，$M_1 = M_2 \implies T_1 = T_2$。

CPA: 否！ | CCA: 否！
工業代表：舊版 SSH (歷史包袱)
MAC-then-Encrypt (MtE) 極易踩坑
$T := \text{MAC}(K_m, M)$
$C := \text{Enc}(K_e, M \parallel T)$
傳輸：$C$

結構弱點：解密者必須先解密才能查驗 Tag。一旦解密或 Padding 報錯，立即淪為 Padding Oracle！

CPA: 是 | CCA: 視情況 (易破)
工業代表：舊版 SSL/TLS (POODLE 苦主)
一秒速記法則：
  • Encrypt-then-MAC (EtM)：永遠最安全。因為 MAC 保護密文，任何篡改在解密前就被擋掉，從源頭抹除任何 Format/Padding Oracle！
  • Encrypt-and-MAC (E&M)：連 CPA 都不保證！因為明文 Tag 洩漏重複訊息。
  • MAC-then-Encrypt (MtE)：必須先碰解密才能看 Tag，產生側信道與 Padding 漏洞。
SECTION 6

認證加密 (AE / AEAD) 與 AES-GCM 現代工業標準

1. 認證加密 (AE) 與 CCA 安全性的嚴格層級關係

CCA 安全性只保證攻擊者構造的密文「解密不出有用的明文資訊」；但認證加密 (AE) 要求更嚴苛：所有非合法密鑰持有者生成的密文，解密結果必須一律為錯誤 `err`！

$$\mathbf{\text{AE Security} \implies \text{CCA Security} \implies \text{CPA Security}}$$
反之不成立（$\text{CCA} \not\implies \text{AE}$）。AE 兼具機密性（Confidentiality）與真實完整性（Authenticity），是現代密碼學的黃金標準。

2. AES-GCM：Galois/Counter Mode（投影片 P.68-73）

TLS 1.3 核心
AES-GCM 架構雙核心
  • 加密層：AES in CTR 模式（提供機密性，支援完全平行化）。
  • 認證層：GHASH（在有限體 $GF(2^{128})$ 上的多項式乘法運算）。
  • Tag 計算：$T = \text{GHASH}_H(A, C) \oplus \text{AES}(K, N \parallel 0)$。
  • 金鑰衍生：Hash 子金鑰 $H = \text{AES}(K, 0^{128})$。
GHASH vs. HMAC 效能與特性比較
  • 極致速度：硬體加速指令（Intel `PCLMULQDQ`）加持下比 HMAC 快 15 倍！
  • 單次走訪 (Single-pass)：加密與 Tag 計算可同步流水線處理。
  • 局限性：GHASH 是帶金鑰函數（Keyed），若無密鑰完全不具備抗碰撞性；且具備線性結構，嚴禁用於公開雜湊（不可取代 SHA-256）！
⚠️ AES-GCM 致命工程禁忌：絕對不可重複使用 Nonce！

如果在相同的密鑰 $K$ 下重複使用了 Nonce $N$： 1. CTR 模式的金鑰流相同，直接造成明文 XOR 洩漏； 2. GHASH 的多項式方程可被攻擊者直接求解未知數 $H$，導致認證金鑰完全洩漏，攻擊者往後可任意偽造所有密文的合法 Tag！

3. 重放攻擊（Replay Attack）與關聯資料（Associated Data / AEAD）

情境（投影片 P.77-79）：Alice 發送了合法密文 $C = \text{Enc}(K, \text{"family-recipes.txt"})$。在「請顯示檔案」的情境下是安全的；但攻擊者截獲 $C$ 後，在 Bob 詢問「請刪除檔案」時重放該密文 $C$，Bob 解密通過（非 `err`），直接誤刪重要檔案！

解法：AEAD (Authenticated Encryption with Associated Data)

將上下文訊息（Context，如 `"ACTION: DISPLAY"`、協定版本、時間戳記、封包序號）作為關聯資料 $A$（Associated Data）傳入： $$\text{Enc}(K, A, M) \to C, \quad \text{Dec}(K, A, C) \to M \text{ 或 } \mathbf{err}$$

當攻擊者在刪除情境重放密文時，Bob 以 $A' = \text{"ACTION: DELETE"}$ 進行解密，由於 Tag 與 $A$ 強力綁定，解密立即報錯 `err`，完美杜絕重放與語境錯置！
SECTION 7

期末精選全真模擬題庫（附逐步詳解）

題目 1・觀念題 配分：15 分
試問為什麼 Encrypt-and-MAC 範式連最基礎的 CPA 安全性都無法保證？請簡要推導其邏輯。

標準解答：

1. 在 Encrypt-and-MAC 範式中，密文形式為 $C \parallel T$，其中 $T = \text{MAC}(K_m, M)$ 是直接對「明文 $M$」計算而得。

2. 標準的 MAC 演算法（如 HMAC、CBC-MAC、PRF）通常為確定性函數（Deterministic）。

3. 攻擊者選擇兩個相同明文 $M_0 = M_1$ 查詢加密預言機，雖然密文 $C_0, C_1$ 因隨機性而不同，但生成的認證標籤必定相等：$T_0 = T_1$。

4. 若攻擊者送出兩個相異明文，則 $T_0 \neq T_1$。因此攻擊者可直接透過比對 Tag 的相等性判斷明文是否重複，破壞了「密文不可區分性」，故連 CPA 安全性都不滿足。

題目 2・證明題 配分：20 分
設 $\Sigma$ 為 CTR 模式對稱加密，現有一解密預言機 $O(C)$：若 $\text{Dec}(K, C)$ 的首個 byte 為 `0xFF` 則回傳 1，否則回傳 0。請寫出區分器 $\mathcal{A}$ 的虛擬碼，並計算其破解 CCA 安全性的 Advantage。

標準解答：

Adversary A:
    M := 0x00 || 0x00...00 (長度 lambda)
    C := cca.enc(M)
    C' := C ^ (0xFF || 0x00...00)   // 僅翻轉首個 byte
    M' := cca.dec(C')
    return M'[0] == 0xFF

優勢計算：

在 Real 庫中：$M'[0] = 0x00 \oplus 0xFF = 0xFF$，恆成立，$\Pr[\text{Real}] = 1$。

在 Rand 庫中：$C'$ 未被快取，解密出均勻隨機明文，首 byte 剛好為 `0xFF` 的機率為 $1/256$。

$$\text{Adv} = |1 - 1/256| = 255/256 \approx 1 \quad \text{(Non-negligible)}$$

題目 3・計算題 配分：15 分
在 PKCS#7 Padding Oracle 攻擊中，若要解密一個由 3 個區塊組成的 CBC 密文（區塊大小 16 位元組），最壞情況下攻擊者需要發起幾次解密預言機查詢？若改為真正明文窮舉需幾次？

標準解答：

1. 密文有 3 個區塊，除去初始向量 IV（第 0 塊），共有 2 個待解密區塊（共 $2 \times 16 = 32$ 位元組）。

2. Padding Oracle 每個 byte 最多測試 256 種可能（$0x00$ 至 $0xFF$）。

3. 最壞情況查詢次數為：$32 \times 256 = \mathbf{8,192 \text{ 次}}$（實務中平均只需 $32 \times 128 = 4,096$ 次）。

4. 若為真正暴力窮舉明文，複雜度為 $256^{32} = 2^{256} \approx 1.15 \times 10^{77}$ 次（計算上不可行）。
